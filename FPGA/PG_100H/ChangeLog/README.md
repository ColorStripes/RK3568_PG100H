# FPGA 项目变更记录（Change Log）

本目录记录了 FPGA 项目各快照之间的变更。快照存放在名为 `yolo_fpga_<MMDD>_<n>`（以及后来的
`yolo_fpga_hdmi_ov5640_<MMDD>_<n>`）的文件夹中，相关文件位于“https://github.com/EdwardMonty/PG100H_YOLOV5n_TestProject ”，其中四位数字表示日期（月/日），末尾的
`_<n>` 表示同一天产生的多个版本。

## 作品概况

* **竞赛**：第十届全国大学生集成电路创新创业大赛 ——「紫光同创」企业命题
* **作品名称**：基于紫光同创 FPGA 的智能交通感知系统
* **队伍编号 / 队名**：CICC1000893 / 彩色条纹
* **硬件平台**：RK3568_MES2L100H 开发板，FPGA 器件为 **紫光同创 PG2L100H**（Logos-2 系列）

FPGA 端的核心工作：以 **纯 RTL 完整部署 YOLOv5n**（总参数量 1.9M，INT8 定点量化），
实现**车牌位置检测**，输出边界框坐标；检测结果与全帧图像经 **PCIe 2.0 x2** 交由主机侧做后续
处理。

## 硬件架构概述

| 子系统 | 目录（位于 `source/` 下） | 说明 |
|---|---|---|
| NPU 计算数据通路 | `npu/` | YOLOv5n 的 6 类硬件算子：`conv`（3×3）、`conv11_16`（1×1）、`cat_add`（拼接/相加）、`sppf`（5×5 最大池化）、`focus`（下采样）、`upsample`（上采样）；`out_buf`/`para` 为输出缓存与数据切换，`reg` 为寄存器/CSR |
| 图像输入 | `ov5640/` | OV5640 摄像头（720p DVP，PCLK=76MHz，30.18fps，RGB565）采集与 CDC |
| HDMI 视频输入 | `HDMI/`（07-04 新增） | MS72xx HDMI 收发器控制（`hdmi_top`、`hdmi_loop`、`iic_dri`、`ms72xx_ctl`），支持 **1080p TMDS** 输入源 |
| 存储 | — | DDR3 控制器（PHY + 用户逻辑），FPGA 侧帧缓存 |
| PCIe 端点 + DMA | `pcie2npu/`、`pcie_dma/` | FPGA 侧 PCIe 2.0 x2 端点 + 内部 DMA（DDR3 → 主机内存搬运） |
| AXI 互连 | `axi_crossbar/`、`axi_dma/` | 7×3 交叉开关、AXI stream/data FIFO、CDC 桥 |
| 顶层 | `top.v` | 连接所有模块；使用互斥的 `USE_OV5640` / `USE_HDMI` 编译开关切换输入源 |
| 约束 | `constraints/` | `.fdc` 时序/布局约束（`cdc`、`ddr3`、`ov5640`、`pcie`、`clock`）、`ddr3.rcf` |

NPU 配置（各算子的通道并行度、分块尺寸、权重长度、数据位宽、算子运行策略等）集中在
**`source/npu/npu_top/config.v`**，采用「全流水线调度配置文件」形式，可自定义网络层数、
并行度与数据位宽。大多数「调优」提交只修改该文件。

## 关键技术要点

* **INT8 定点量化数据通路**：图像采用非对称量化、权重采用对称量化；激活函数用线性 **ReLU**
  取代原 SiLU，避免指数运算带来的资源开销。量化尺度/零点/偏移（scale / zero / bias）及其
  融合系数（s₁s₂/s₃）直接体现为 `conv_mul` / `scale_mul` 等乘法器模块的设计。
* **MAC 资源优化**（`conv_mul`）：将 8bit 被乘数 A、8bit 零、8bit 被乘数 B 拼接后与 8bit
  乘数 C 相乘，借助乘法分配律一次得到 16bit `C·A` 与 16bit `C·B` 的拼接，直接映射为紫光
  **APM_E2** 原语，大幅降低 DSP（MAC）占用。
* **算子复用与三路并行数据流**：以 6 类硬件算子支撑网络所需的 7 种运算；三路并行数据流
  A/B/C 提升吞吐。
* **FPGA 内部 DMA 改进**：将官方 DMA IP 的「DRAM 地址读取」逻辑改为「FPGA 侧 DDR3 地址读取
  + 配套地址逻辑」，实现 DDR3 数据经 PCIe 高效搬运至主机内存。
* **PCIe 端点与 DMA 控制器**：BAR1 承载 PIO 控制、BAR2 作数据交换空间；为 DMA 控制器新增功能
  寄存器（0x1E0～0x250），TLP 固定 4096 字节、4 字节（DW）对齐，支持 MSI 中断，双向链路速率
  约 **800MB/s**。
* **双输入源接收**：摄像头控制寄存器模块重构为双向兼容结构，支持 720p OV5640（DVP）与 1080p
  HDMI（TMDS）双路输入；通过 20ms 硬件消抖 + 场消隐期状态机切换，无半帧乱序。

## 关键指标

* 部署的 YOLOv5n 在 640×640 RGB888 输入下 mAP = **0.96**。
* PG2L100H（APM 240）：单帧推理 **58.14ms**；1×1 卷积并行度 16×8、3×3 卷积并行度 16×2。

## 如何阅读本变更记录

* 每天对应一个 Markdown 文件，例如 `0510.md`，涵盖当天所做的每一次版本修改。
* 每个更新小节列出 **修改 / 新增 / 删除** 的源文件，总结有意义的变更（参数调整、数据通路重写、
  新外设），并展示从各构建的 `multiseed_summary.csv` 中提取的 **资源 + 时序差异**。
* 资源数据为 *器件映射（Device Map）* 总量：**LUT**（逻辑）、**FF**（触发器）、
  **DRM**（块 RAM，共 155 个）、**APM**（DSP 乘法器，共 240 个）、**DistRAM**
  （分布式 RAM）。“Util” 表示 LUT 占可用 66,600 个的利用率。
* **Synth WNS** = 综合后的最差负时序裕量。**P&R setup** = 布局布线后的建立时间裕量
  （正值 = 时序满足；负值 = 时序违例）。
* 若快照的 `multiseed_summary.csv` 中显示 `Used = NA`，则表示该构建为 **未完成 / 失败的构建**
  （布局布线收敛率为 0%）。其源码变更仍会记录。

## 关键转折点

1. **05-10 → 05-12** — 对 1×1 卷积输出通道并行度（`CONV11_CHA_PAR_OUT`）进行密集调优，
   在 4 → 2 → 8 → 2 → 4 → 2 之间循环，使 LUT 用量在约 36K 到 50K 之间波动。技术文档给出的
   最终 PG2L100H 配置为 1×1 卷积 16×8、3×3 卷积 16×2（APM 240，58.14ms）。
2. **05-11（0511_0）** — 对乘法器数据通路进行大规模重写（`conv_mul`），即「8bit A + 8bit 零
   + 8bit B 拼接后 × 8bit C」的 MAC 优化，新增有符号量化缩放乘法器变体（`*_s3`，对应量化系数
   s₁s₂/s₃）。该构建一度将 DSP/APM 用量降为 0、LUT 降至约 10K，随后在 0511_1 中恢复完整 NPU。
3. **07-04** — 新增 **HDMI 视频输入子系统**（新的 `HDMI/` 目录树和 `clock.fdc`），实现
   720p OV5640（DVP）与 1080p HDMI（TMDS）**双输入源**支持。项目更名为
   `yolo_fpga_hdmi_ov5640`，顶层增加互斥的 `USE_OV5640` / `USE_HDMI` 编译模式。
4. **07-04 → 07-05** — 0704 构建运行在 *HDMI 输入* 模式（摄像头 + NPU 未编译，约 9.5K LUT）；
   0705 重新启用 *OV5640 + NPU* 通路（约 42K LUT）。
